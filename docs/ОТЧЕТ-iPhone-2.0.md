`played_s` уточняется по реально прошедшему времени, сохраняется периодически, при паузе и смене песни. Перемотка не добавляет секунды. Повтор push не создаёт второе прослушивание.

Причина старого дефекта next/previous: правило `ios/` в `app/.gitignore` исключало также `modules/mwave-remote/ios`. Модуль существовал на диске, но отсутствовал в GitHub-сборке; optional NativeModule скрывал отсутствие. Правило заменено на `/ios/`, Swift и podspec добавлены в Git. `check-native-module.mjs` проверяет tracked-файлы, Expo autolinking и Podfile.lock. Модуль также уточняет длительность и playbackRate шкалы Now Playing, включая паузу.

## Сервер и откат

Дополнительной службы аккаунтов нет. Deno mwave проверяет access через существующий `127.0.0.1:8782/account-api/v1/me` перед каждым защищённым запросом. Пароль/refresh не передаются. Положительного кэша после отзыва нет. Ошибка проверки: 503, плохая/отозванная сессия: 401.

`server/src/account-audio.ts`: непрозрачные ссылки с владельцем и TTL. Bearer нужен для HTTP и всех частей HLS: плейлистов, ключей, инициализации, сегментов. Заголовок аккаунта внешнему CDN не передаётся. Range сохраняется; HTTPS-перенаправления проверяются. Живая проверка выявила используемый `playback.media-streaming.soundcloud.cloud`; он поддержан вместе с sndcdn.com и покрыт тестом.

На аккаунт: 240 API/мин, 60 тяжёлых/мин, 600 звуковых/мин; 429 с понятной ошибкой. Для общего ключа остаются IP-лимиты. Ключ временно работает для ПК, старого телефона и монитора; в новый клиент/репозиторий/CI он не добавлялся. Позднее `MWAVE_ALLOW_LEGACY_KEY=0` отключает ключ и старые `/s/`. Перед этим надо перевести все старые клиенты и монитор на аккаунты.

Точный список серверных изменений:

1. `/opt/mwave/app/mwave-server.mjs`.
2. `/etc/systemd/system/mwave.service`: к разрешению Deno на запись добавлены только `/opt/mwave/cache/lyrics` и `/opt/mwave/cache/charts`.
3. Два каталога кэша, владелец mwave, права 750.
4. Приватная копия `/var/backups/mwave-before-iphone-2-20261029-175152`.

nginx, аккаунтный сервис, VPN, боты и монитор не менялись. QA-аккаунты/сессии удалялись в finally; пароль и медиатека владельца не использовались.

Копия: 279 108 556 байт, 8 файлов на момент создания. SHA-256 mwave.tar: `367b1788b0ab7a99179c56482351acc56ce3a6c585e6427c39515c89d5769fb9`. Архив содержит /opt/mwave, unit, nginx-конфигурацию и монитор. База аккаунтов снята штатным SQLite backup, integrity_check=ok; rotation.key/covers скопированы приватно. Позднее добавлены промежуточные рабочие пакеты и unit перед кэшем.

Был сбой выкладки: кэш не укладывался в Deno `--allow-write=/opt/mwave/logs`, служба перезапускалась. Рабочий пакет возвращён, затем после копии unit разрешены два каталога. После исправления NRestarts=0. Проверены active: mwave, mwave-accounts, nginx, swiftvpn-bot, cabbit-giveaway, ngok-bot, ngok-api, ngok-notifications, webconfig, xray, mwave-health.timer.

MemAvailable до работ 785 MiB, перед копией 749 MiB, после итоговой живой проверки 859 MiB. После старта новой службы наблюдалось 24 MiB текущей памяти / 63 MiB пика, после запросов пик около 88 MiB. Это измерения выполненных проверок, многопользовательского нагрузочного теста не было. Порог остановки 150 MiB не достигался. Новый Node-процесс не добавлялся.

Откат только этих изменений, root shell:

```bash
set -e
backup=/var/backups/mwave-before-iphone-2-20261029-175152
tar -xOf "$backup/mwave.tar" opt/mwave/app/mwave-server.mjs > /tmp/mwave-restore.mjs
tar -xOf "$backup/mwave.tar" etc/systemd/system/mwave.service > /tmp/mwave-restore.service
install -o mwave -g mwave -m 644 /tmp/mwave-restore.mjs /opt/mwave/app/mwave-server.mjs
install -m 644 /tmp/mwave-restore.service /etc/systemd/system/mwave.service
systemctl daemon-reload
systemctl restart mwave
curl --fail --silent --retry 3 --retry-connrefused http://127.0.0.1:8780/health
systemctl is-active mwave mwave-accounts nginx mwave-health.timer
```

Аккаунтную базу и nginx при этом не восстанавливать: иначе будут потеряны новые пользовательские изменения. Каталоги кэша можно оставить. Сама процедура полного отката в production не прогонялась; возврат рабочего пакета при сбое выполнялся.

Первый живой запуск: 7 запросов к mwave, обнаружен новый CDN. Диагностика: 2 запроса с кэшем. Итог: 9 запросов. Всего 18 за исправление, без массового прогона песен. Прямых YouTube-запросов с домашнего ПК не было. Холодная подготовка вместе с начальным HTTP: YouTube 3 865 ms, SoundCloud 3 668 ms. Менее 2 s для подготовленных песен на iPhone пока не измерено и не объявляется достигнутым.

`patch-sqlite-web.mjs` исправляет две ошибки Expo SQLite 16.0.10: обрезание длины ответа до байта и зависимость ожидания от числа итераций CPU. Version-checked postinstall патч меняет только веб-мост. Альтернатива: отдельный web-storage, но тогда веб перестал бы проверять ту же SQL-модель. iOS использует штатную native SQLite.

Для звука сохранён expo-audio с небольшим Swift-модулем. Альтернатива react-native-track-player требовала бы замены работающего движка и ещё одной нативной миграции. Ни один вариант не отменяет физическую приёмку фоновых/аппаратных команд.

Workflow ручной, кэши npm/CocoaPods/Xcode. JSON времени сборки выгружается с IPA. Нативная проверка использует синтетический тон и локальный HLS; временный TLS-сертификат доверяется только тестовому симулятору. Проверяются модуль, Swift-события, AVPlayer progress/seek/pause и Bearer в HLS. На устройстве методы симуляторного теста не компилируются.

| Run | Причина |
|---|---|
| 7, 40865084991 | Остановлен до Xcode: загрузка Chromium зависла после 100%; IPA не компилировался |
| 8, 40867087662 | Chrome runner; веб выявил CPU-зависимое ожидание worker. До Xcode не дошло |
| 9, 40868336442 | Успешно: нативная проверка и первый IPA; итоговый IPA пересобирается с двумя проверенными исправлениями плеера |
| Итоговый запуск | Объединённые исправления нулевой позиции при ошибке и повтора недоступной песни; результат будет внесён после завершения |

Используется Chrome из [официального образа GitHub macOS ARM64](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-arm64-Readme.md), отдельная загрузка браузера исключена. Предварительный шаг ограничен 6 минутами, логи выгружаются при ошибке.
