## 1. Что сделано

### Приложение (`app/`)
React Native 0.81.5 + Expo SDK 54, новая архитектура, Hermes. Такая же цепочка, как в Cabbit iOS Test.

| Часть | Файлы |
|---|---|
| Вход, навигация, ссылки `mwave://` | `src/App.tsx`, `src/nav.ts`, `src/launchArgs.ts` |
| Ключ сервера: ввод при первом запуске, хранение в Связке ключей | `src/key.tsx`, `src/api.ts` |
| Тема (светлая и тёмная по системе), цвета ПК, шрифт Onest | `src/theme.ts`, `src/pc/shared/theme.ts` (копия ПК) |
| Плеер: очередь по источникам, перемешивание, повтор, волна, ссылки заранее, повтор при сбое | `src/player/core.ts` |
| Звук: фон, экран блокировки, Пункт управления | `src/player/expoEngine.ts` |
| «Следующая» и «предыдущая» с экрана блокировки и наушников | `modules/mwave-remote/` (свой модуль на Swift, MPRemoteCommandCenter) |
| Профиль на телефоне (SQLite): избранное, плейлисты, история, избранные артисты с новыми релизами | `src/profile.ts`, `src/state.tsx` |
| Экраны | `src/screens/HomeScreen.tsx`, `SearchScreen.tsx`, `ArtistScreen.tsx` (артист и альбом), `LibraryScreen.tsx`, `NowPlayingScreen.tsx` (плеер и очередь) |
| Стеклянная капсула навигации и мини-плеер над ней | `src/ui/TabBar.tsx`, `src/ui/kit.tsx`, `src/ui/Page.tsx`, `src/ui/icons.tsx` |

Логика из проекта ПК переиспользуется копиями (скрипт `scripts/sync-pc.mjs`, в каждой копии пометка «Не править здесь»):
`queueLogic`, `searchRank` («Лучший результат»), `format` (подписчики по-русски), `match`, `artistNames`, палитры темы.

Функции: поиск с «Лучшим результатом», карточки артиста и альбома, популярные песни с «Показать ещё», волна,
очередь по источникам, перемешивание и повтор, избранное, плейлисты, история, избранные артисты с отметкой
новых релизов, полноэкранный плеер с размытым фоном. Импорт пропущен (по заданию), профиль локальный.

### Изменения после переписки
1. Репозиторий сделан публичным. Ключ в приложение не вшит: при первом запуске экран «Ключ сервера», проверка на сервере, сохранение в Связке ключей.
   Секрет `MWAVE_KEY` в GitHub используется только для снимков в симуляторе и вырезается из журнала.
2. В симуляторе звук не играл: AVPlayer на iPhone не умеет WebM/Opus, а YouTube отдавал именно его. На сервере yt-dlp теперь выбирает M4A (AAC).
3. AVPlayer у M4A из YouTube показывал неверную длительность (5:35 вместо 2:48). Приложение теперь берёт длительность из каталога, если расхождение больше 10 %.
4. Капсулы навигации и плеера опущены ниже, подпись лучшего результата в две строки.

## 3. Решения и альтернативы

| Решение | Альтернативы | Почему так |
|---|---|---|
| React Native + Expo, сборка без подписи на GitHub | Swift/SwiftUI; Flutter; Capacitor | Проверенная цепочка Cabbit; TypeScript позволяет взять логику ПК без переписывания |
| Свой модуль Swift для «следующая/предыдущая» | react-native-track-player | expo-audio даёт только пуск, паузу и перемотку; track-player тянет свою очередь и конфликтует с ядром из ПК |
| Ключ вводится один раз, хранится в Связке ключей | вшить в IPA; вход по логину | Публичный репозиторий и IPA нельзя считать секретом; логины не нужны для одного пользователя |
| Публичный репозиторий | частный + платные минуты | Для частного репозитория GitHub заблокировал сборку из-за оплаты; публичный бесплатный; секретов в коде нет |
| Сервер выбирает M4A (настройка yt-dlp) | перекодировать звук на сервере в AAC | Перекодирование нагружает 1 ядро сервера; M4A у YouTube есть у всех песен, команда как на ПК |
| Длительность из каталога при расхождении | перепаковывать поток на сервере | Не нагружает сервер, показывает ту же длину, что и в списке |
| Снимки в симуляторе через аргументы запуска | `simctl openurl` | `openurl` показывает системное окно «Open in mwave?» и снимки застревают |

## 5. Риски

1. **Бесплатный Apple ID:** подпись 7 дней, не больше 3 таких приложений на телефоне, 10 новых ID приложений за неделю. Раз в неделю нужна переподпись в Sideloadly (данные сохраняются, если не удалять приложение).
2. **Без телефона не проверено:** фон, экран блокировки, наушники, мобильная сеть (список выше).
3. **YouTube меняет защиту:** yt-dlp обновляется на сервере каждый день; при поломке звук YouTube пропадёт до обновления, SoundCloud продолжит работать.
4. **Длительность на экране блокировки** iOS берёт из плеера, там у части песен YouTube может быть неверная длина (в приложении исправлено). Если подтвердится на телефоне, следующий шаг: передавать длительность в свой модуль Swift.
5. **Ключ:** если ключ попадёт к посторонним, сервером смогут пользоваться они. Смена ключа: новый файл `/opt/mwave/secret/token` на сервере, перезапуск `mwave`, ввод нового ключа в приложении («Медиатека → Сменить ключ сервера»).
6. **Сервер слабый** (1 ядро, около 1 ГБ свободной памяти): одновременно не больше 2 запросов к yt-dlp, при нескольких пользователях подготовка песни может занимать несколько секунд.
7. **Публичный репозиторий:** код виден всем; секретов и адресов, кроме домена сервера, в нём нет.
